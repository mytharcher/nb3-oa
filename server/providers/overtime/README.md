# 加班后端

`oa.overtime` 使用审批插件公共 `ApprovalService`，当前只有后端 API，没有申请和审批客户端页面。API 基路径 `/overtimeRequests`；输入为 `date`（平台日历本地日期）、`minutes`（1–1440 的整数分钟）、`settlement`（`compensatory` / `pay`）、`reason`。接口支持草稿创建、编辑、提交、撤回、管理员终止和插件提供的审批操作。

提交事务锁住申请人用户，检查在职档案及同日在途/已批申请。月累计包含本单与同月在途/已批单，超过快照规则 `overtime.monthlyHead`（小时）进入部门负责人；加班日期之后超过 3 个平台工作日进入 HR 或签。当前阶段 API 仅接受静态 SLA，非默认 24/48 工作小时规则明确拒绝提交。

批准后，加班费结算写唯一考勤事实；调休结算逐分钟保留来源批次，固定 240 分钟转换为一个半天，剩余分钟累计。每批自加班日期起 3 个日历月，月底夹至目标月份最后一天，该日结束后的平台本地午夜为半开到期端点。FIFO 合并批次生成的半天取参与来源的最早到期，防止延长旧额度。`overtimeMinuteConversions.sources` 保存各批次消耗；维护任务将到期余数转入 `expiredMinutes`，保留原始分钟和转换历史。所有事实与余额 grant 在批准事务内提交，重复审批不重复结算。

维护任务使用独立 `oa-overtime` jobs scope，每 10 分钟执行审批时钟、无审批人/升级到链顶告警、余数过期、生命周期恢复，并只清理 30 天前成功或取消的副作用尝试，不清理审批及审计历史。
