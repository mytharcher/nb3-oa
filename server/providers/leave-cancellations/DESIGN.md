# 销假

独立申请 `leaveCancellations` / `oa.leaveCancellation`，只允许原单申请人发起。原已批请假内容及审批历史保留，当前有效范围以 `leaveAttendance` 为准。全单取消必须在起始半天开始前获批；缩短仅取消新的结束半天之后的部分。提交和最终通过均使用平台 Calendar 时区与工作时段检查取消范围尚未开始。

| 环节      | 人员来源                                                                | 动作                                                                                           | 结果                                |
| --------- | ----------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------- | ----------------------------------- |
| 草稿/修改 | 本人                                                                    | 编辑、提交、撤回                                                                               | 提交确认                            |
| 单人确认  | 原请假最后一次成功第 1 环节的负责审批人；历史数据回退 managerApproverId | 同意、拒绝（理由）、退回修改（理由）、评论、转办、前置/并行加签、申请人催办、管理员指定/重分配 | 通过执行退款和考勤修正；空人员 hold |

审批任务 24/48 工作小时提醒与升级；独立 `oa-cancellation` jobs 维护。原单批准历史不可再改变，通过公共 API 在创建销假事务前解析原审批人，避免跨 runtime 开启独立嵌套事务。业务批准前重查原单状态和申请人。

| 时点           | 原子业务效果                                                                                                                  |
| -------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| 提交           | 锁申请人；验证已批原单和未开始取消范围；快照有效考勤范围、退还工作日                                                          |
| 同意           | 同事务锁申请人并比较考勤基线；按原扣减类型快照退还半天整数（原批次到期规则保留）；缩短考勤或 active=false；失效自动委托；审计 |
| 拒绝/撤回/终止 | 保留原单、余额、考勤与委托                                                                                                    |
| 通知           | 持久化 lifecycle effects，Approval 公共任务通知                                                                               |

`POST /api/leaveCancellations` 内容为 `{ originalLeaveId, cancelAll, endDate, endHalf, reason }`。全单取消仍传原单结束日期与半天，核算忽略这两个值。edit 只能改表单字段，不能换原单。其余 list/detail/transition/action 结构同请假；days 为本次退还天数，baseline 为提交时有效考勤快照。

同原单多个申请可等待；一个通过后其他申请若考勤基线已变则整次批准与退款回滚，须退回重算。退款 requestKey 对销假唯一；退款上限由余额服务按原单扣减负责，不生成新的无来源余额。
